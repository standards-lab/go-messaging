## Task brief · core-event

```
Problem       Emitters and reactors need one CloudEvents type and one emission
              contract that names no broker and no database. spike-messaging
              proved it in its core/event; go-core takes it on the standard
              library alone, so domains, SDKs, and go-messaging can name events
              without a broker dependency, and go-messaging's library task can
              pin it.
Behaviors     1. An Event round-trips through Encode/Decode in binary mode:
                 ce-prefixed attributes, content-type as datacontenttype, data
                 as body, extensions as other ce- headers; time in RFC3339 UTC.
              2. Decode matches header names case-insensitively (lowercase
                 wins), requires specversion 1.0, and rejects an event that
                 Validate rejects.
              3. Validate reports every missing id, source, and type, and every
                 extension name that is empty, not lowercase alphanumeric, or a
                 context attribute's name; long names pass.
              4. CheckType accepts dot-separated tokens and rejects empty
                 tokens, whitespace, control characters, '*' and '>'; Define
                 panics on a type CheckType rejects.
              5. Raise queues an unstamped event with JSON data and its content
                 type; an encode failure is held on the Queue; Queue.Events
                 returns a copy.
              6. Recorder.Emit, on success, stamps each queued event (a UUIDv7
                 id by default, the recorder's source, one UTC time) and writes
                 them in raise order through the Sink in the same Tx; a failing
                 body, raise, or sink writes nothing and fails the command; no
                 raise means no write.
              7. NewRecorder panics on a nil sink or an empty source; Clock and
                 IDs options override the stamp.
              8. Permanent marks an error through further wrapping and keeps
                 errors.Is/As to the cause; Permanent(nil) is nil; IsPermanent
                 detects the mark.
              9. go-core's go.mod gains no requirement; the package's README and
                 doc.go export inventory, go-core's capability map (eight
                 packages), and the CHANGELOG's v0.10.0 section describe event.
Test seams    the package's exported API, black-box (event_test), with a fake
              Tx and Sink
Slices        1. Envelope and codec: Event, Validate, Header, Encode/Decode,
                 SpecVersion (behaviors 1–3). Demo: round-trip and
                 canonical-HTTP-header decode tests.
              2. Kinds and raising: CheckType, Define/EventKind, Queue,
                 Permanent/IsPermanent (4, 5, 8). Demo: Define panics on
                 "a.*"; Raise queues JSON.
              3. Recorder: Sink, Recorder, NewRecorder, Emit, Clock/IDs (6, 7).
                 Demo: a fake transaction sees stamped v7 events only when the
                 body succeeds.
              4. Docs and release prep: doc.go inventory, README, capability
                 map, CHANGELOG v0.10.0 (9). Demo: `go doc ./event`.
Out of scope  typed consumer decoding (go-messaging's Consume); the broker
              contract and messaging's CheckType (library); traceparent
              (v1.observability); header-value CR/LF rejection (providers);
              go-web-service emission (service-events); a depguard rule for
              go-core
Door          one-way at the tag: a published go-core version can't be
              unpublished (pre-1.0, a later minor may still change the API);
              two-way before it
Release       go-core v0.10.0
```


## Decisions

- plan: root is go-messaging, created by this plan; core-reactor names it in `repos` only for the record (the cli precedent, rooted in its new go-cli-sdk while its first task ran in go-core).
- plan: go-messaging takes go-cli-sdk's init set unchanged: kind code, `mise run check`, `mise run currency`, no release gate, plain `gh pr merge` until the library task's CI lands, public on github.com/standards-lab, Apache-2.0; the library task scaffolds the base, `postgres`, and `nats` modules.
- plan: go-core's reactor and event packages are two tasks, core-reactor and core-event, each with its own go-core release; event is new design, the reactor a port of tested code.
- plan: service-reactors runs right after core-reactor, so go-core's reactor is proven on its one real consumer and the service's copies are deleted before events build on it.
- core-reactor: `reactor` ports go-web-service's `sdk.Reactor`, `Every`, `Wake`/`Waker`, `Draining`, and `Gate` with behavior unchanged, plus spike-messaging's `GraceWithin` (renamed `CancelWithin`); the gate is `reactor.Gate`. Rejected: `sync.RWMutex` (can't honor a context) and `x/sync/semaphore` (breaks go-core's standard-library-only line).
- core-reactor: the lifecycle coordination test sits outside the package, so `reactor` imports neither `lifecycle` nor `graph`.
- core-reactor: whether go-web-service uses `CancelWithin` in place of its hand-computed half of the shutdown timeout is decided in service-reactors.
- core-reactor: releases go-core v0.9.0, a minor: the task only adds API.
- core-reactor: currency re-run at start: go-core current; go-messaging has no mise tasks until the library task scaffolds them, so its currency command fails with nothing pinned.
- core-reactor: `Every` and `Wake` share one unexported tick loop (standards review); `Every`'s behavior is unchanged.
- core-reactor: `Gate` stays in `reactor`; the standards review raised a separate home, and the plan had already settled `reactor.Gate`.
- core-reactor: `Waker.Nudge`'s doc says a nudge after the source stops delivers nothing, though the nudge stays pending; left as worded, since it is harmless while a reactor is single use.
- core-reactor: go-core's capability map gains `graph`, which it had been missing; its seven packages count `process/processtest`.
- core-reactor: `Grace(d)` renamed `CancelAfter(d)` before release (BRIEF redirect): it names what happens when d runs out; `DrainTimeout` rejected, it collides with the coordinator's drain timeout.
- core-reactor: `GraceWithin(drain)` renamed `CancelWithin(drain)`; dropping the helper rejected, so the half-the-drain rule stays in one place.
- core-reactor: tests beyond the port cover `Ready` false while `Shutdown` drains, `CancelWithin`, and the start context's and source's values, and the unread-`Err` test was made able to fail.
- service-reactors: the sweeper sets its cancel-after period with `reactor.CancelWithin(shutdown timeout)` in place of computing half the shutdown timeout by hand, so the half-the-drain rule lives only in go-core; value unchanged (5s under the 10s default).
- service-reactors: fixes the three other statements go-core v0.8.0 made untrue ("any Ready joins readiness": composition root's package doc, README's guide to adding a service, readiness test's comment) beside the app.Wake comment.
- service-reactors: currency at plan: Grafana 13.2.3 -> 13.2.4 (patch) and go-core v0.8.0 -> v0.9.0 (adds only `reactor`) go in the upgrade slice; currency missed go-core because the proxy's version list lags the tag, so the slice checks the pin directly.
- service-reactors: the staged reactor and gate tests are deleted without porting, since go-core's reactor tests cover all of them.
- service-reactors: the cancel-after test runs under a 200ms shutdown timeout and pauses briefly after the sweeper reports Ready, so the pass reaches its wait on the gate; a short pause leaves no pass in flight and fails the test, so it can fail spuriously but never pass falsely. Rejected: a deterministic test, which needs a hook on go-core's `Gate` to observe the wait, a go-core change out of scope here.
- service-reactors: the CHANGELOG's [Unreleased] pins line now reads go-core v0.9.0 rather than listing both pins; older pins elsewhere in [Unreleased] (go-core v0.6.0 in the multi-library line, v0.7.0 in the UTC entry) stay, for a CHANGELOG-wide pin cleanup before the first cut.
- service-reactors: `sdk`'s package doc says the package stages request conventions only, dropping "lifecycle conventions" with the reactor and gate.
- core-event: ports spike-messaging's core/event with behavior and exported API unchanged, adding go-core's doc.go inventory, README, and capability-map entries. Rejected: cloudevents sdk-go v2.16.2 (json-iterator, google/uuid, zap, testify break go-core's standard-library-only line).
- core-event: typed data decoding stays in go-messaging's `Runtime.Consume[T]`; no `event.Decode[T]`: a consumer decodes into its own type, and Consume is the one caller.
- core-event: releases go-core v0.10.0, a minor: the task only adds a package.
- core-event: currency at plan: go-core current.
- core-event: Decode converts a parsed `ce-time` to UTC (escalation, utc-times standard), the one departure from the port's behavior-unchanged ruling; the spike returned the parsed zone.
- core-event: Encode writes `ce-time` in UTC as RFC 3339 with nanoseconds (`time.RFC3339Nano`), kept from the spike, so fractional seconds survive a round trip.
- core-event: `event` has no package README, since no go-core package has one; the brief's "package's README" is go-core's README entry and the doc.go inventory.
- core-event: `event`'s doc.go states each contract once and points to `Recorder.Emit`, `Encode`/`Decode`, and `Permanent` for the details (standards review).
