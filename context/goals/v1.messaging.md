## Task brief · library

```
Problem       go-messaging has no code yet. Without it, a service can't emit
              through an outbox, consume idempotently through an inbox, or run
              a consuming reactor on a broker contract, and the nats, template,
              and service-events tasks have nothing to pin. spike-messaging
              proved the design. This task ports its base and postgres engine
              onto go-core v0.10.0 and adds the four things the spike left
              open: the error hook, the delivery attempt, poison-row
              quarantine, and the relay Timeout in Config. Then it releases
              both modules.
Behaviors     1. A Subscription validates and normalizes as the spike's does:
                 Name is a token (CheckName), each Type passes CheckType
                 (go-core's event.CheckType), MaxDeliver, AckWait, and
                 RetryDelay are not negative, and Start is StartAll or
                 StartNew. Normalize defaults AckWait to 30s and sorts and
                 de-duplicates Types (nil when empty). Matches filters on
                 type. Encode rejects what event.Encode or CheckType rejects.
              2. Broker.Subscribe takes a subscription and a report function.
                 A source passes each error it survives (one that doesn't end
                 Receive) to report with its context. A nil report discards
                 them. The memory provider reports a message it can't decode
                 and terminates it.
              3. Each delivery's handler context carries its attempt: 1 on the
                 first delivery, and one more on each redelivery, whether the
                 previous delivery ended in an error or an expired AckWait.
                 messaging's attempt reader returns 0 for a context no
                 provider gave.
              4. The memory provider passes messagingtest. The suite runs the
                 spike's cases unchanged, plus attempt cases: the first
                 delivery is attempt 1, the attempt counts up after an error
                 and after an expiry, and the last delivery of an event
                 bounded by MaxDeliver carries attempt MaxDeliver.
              5. outbox.New and inbox.New refuse an engine that leaves a
                 statement undefined or gives one other parameters, and name
                 each such statement. The outbox engine gains a Quarantine
                 statement, with parameters seq and reason.
              6. The sink writes each event in the command's own transaction,
                 in raise order, and an event whose source and id are already
                 there fails it. Inbox.Claim is first once per consumer,
                 source, and id, and a rolled-back claim is released.
              7. The relay publishes in seq order, one row per transaction,
                 and marks the row published in the transaction that claimed
                 it. Two kinds of row are quarantined at once, with a reason,
                 in that row's transaction, and the pass goes on to the next
                 row: a corrupt row (its header or event doesn't decode) and a
                 row whose publish fails with an error marked event.Permanent.
                 Receive no longer ends on a corrupt row. A transient publish
                 error leaves the row unpublished and ends the pass, as in the
                 spike, and counts toward nothing. Each quarantine, each pass
                 a transient publish error ends, and each database error
                 reaches the relay's report function. Ready, Timeout, Drain,
                 and the transaction bound at twice the Timeout keep the
                 spike's behavior.
              8. Config gains relay_timeout: 10s by default, overridden by
                 <PREFIX>_MESSAGING_RELAY_TIMEOUT, overlaid by Merge, and
                 required to be positive. Runtime.Relay applies it as the
                 relay's Timeout.
              9. messaging.New takes an Option that sets the error hook,
                 func(ctx, Failure). Without one, each Failure is logged at
                 warn on the Runtime's logger. A Failure names its kind
                 (relay, quarantine, source, or exhausted), the consumer when
                 there is one, the event's identity when it is known, the
                 attempt, and the error.
              10. Runtime.Consume's reactor reports exhaustion to the hook when
                 its handler returns an error not marked permanent on the
                 attempt that equals the subscription's MaxDeliver (only when
                 MaxDeliver > 0). It reports the source's survived errors as
                 source failures, and the relay's reports as relay or
                 quarantine failures. Otherwise Consume and Relay keep the
                 spike's behavior: decoding, the inbox claim, the per-delivery
                 log lines, and the relay's last pass at a quarter of the
                 drain timeout. Both use reactor.CancelWithin(drain), and
                 nothing registers with lifecycle.
              11. The postgres module ships the `messaging` migration set: one
                 migration holding both tables, every object prefixed
                 messaging_, and a down that reverts it. messaging_outbox
                 carries quarantined_at and a quarantine reason, and its
                 unpublished index leaves quarantined rows out. A golden-hash
                 test pins the migration's text.
              12. The postgres engine's statements satisfy outbox.New and
                 inbox.New. Its claim skips quarantined rows, and every
                 statement that writes declares its transaction. Verify fails
                 on a schema without the set, and Pending counts the rows
                 awaiting publication, quarantined rows excluded. The spike's
                 integration suite passes against Postgres, with quarantine
                 cases (corrupt row and permanent failure) in place of
                 "corrupt row ends the relay".
              13. The base module's production files import only the standard
                 library, go-core, sqlate, and sqlate/query; its test files may
                 also import sqlate/sqltest. A depguard rule fails the check on
                 any other import. Every module builds with the workspace off.
              14. CI runs the check on every pull request and every push to
                 main. It runs the postgres integration suite on push to main
                 and on manual dispatch, against the repository's compose
                 Postgres. A pushed tag creates that module's GitHub release
                 from its changelog. The main ruleset requires a pull request
                 and forbids deleting or force-pushing main. Dependabot
                 security updates are on, with no version-update config. The
                 session's merge waits on the pull request's checks, and its
                 ci wait covers main's push runs, the integration job
                 included.
              15. These describe the shipped modules: the README (its
                 dependency line admitting sqlate and sqlate/query into the
                 base), STANDARDS.md's dependency line, each package's doc.go
                 export inventory, the context capability map, and the
                 changelogs (base v0.1.0, postgres v0.1.0, nats
                 [Unreleased]).
Test seams    each base package's exported API, black-box: messaging,
              outbox, and inbox over sqlate's scripted driver and the memory
              broker, and providers through messagingtest.Run. The postgres
              package's exported API runs against a scratch Postgres database
              under the integration tag.
Slices        1. Scaffold: the base, postgres, and nats modules with a
                 committed workspace; the check, currency, and upgrade tasks;
                 the depguard rule (13); pins at latest (go 1.27.2,
                 golangci-lint 2.14.0, and go-core v0.10.0, sqlate v0.5.0,
                 sqlate/postgres v0.5.0, sqlint v0.3.0, and pgx v5.11.0 as
                 the code that imports each lands). Done when currency exits
                 0 and the check passes. Demo: `mise run check`,
                 `mise run currency`.
              2. Broker contract, attempt, memory, conformance (1–4). Demo:
                 memory's conformance run, including attempt reaching
                 MaxDeliver.
              3. Outbox and inbox: engine contracts with Quarantine, the sink,
                 the relay's quarantine and report function, the inbox claim
                 (5–7). Demo: a corrupt row and a permanently failing row are
                 quarantined and the next row publishes.
              4. Runtime: Config relay_timeout, New with the hook Option,
                 Relay, Consume with exhaustion and source-failure reporting
                 (8–10). Demo: hook gets one exhausted Failure on attempt 3 of
                 MaxDeliver 3; the default hook's warn line.
              5. Postgres engine: migration set with quarantine columns and
                 golden hashes, statements, Verify, Pending, scratch-database
                 helper, compose Postgres, integration task and suite (11, 12).
                 Demo: `mise run integration`.
              6. CI and repository settings: CI workflow (check job,
                 integration job), release workflow, main ruleset, Dependabot
                 security updates, the session's merge and ci configuration
                 (14). Demo: PR check job green; ruleset and security-update
                 state read back through the API.
              7. Docs and release prep: README, STANDARDS.md, doc.go
                 inventories, capability map, three changelogs (15). Demo:
                 `go doc ./outbox`, the README's dependency line.
Out of scope  the nats provider beyond its scaffold, stream ownership, and
              the nats integration run (nats); a dead-letter stream; outbox
              and inbox retention (sweeper); holding the gate around the
              relay and claims (service-events); traceparent
              (v1.observability); migrating a durable's binding config;
              InactiveThreshold; the change-only event pattern; the spike's
              split-check; a depguard rule on the postgres or nats module;
              an attempt bound for transient relay failures
Door          two-way before the tags: code, CI, and repository settings are
              reversible. One-way at the tags: a published module version
              can't be unpublished, and once postgres/v0.1.0 ships the
              messaging set's first migration is frozen (pre-1.0, a later
              minor may still change the API)
Release       v0.1.0, postgres/v0.1.0
```

## Decisions

- plan: root is go-messaging, created by this plan; core-reactor names it in `repos` only for the record (the cli precedent, rooted in its new go-cli-sdk while its first task ran in go-core).
- plan: go-messaging takes go-cli-sdk's init set unchanged: kind code, `mise run check`, `mise run currency`, no release gate, plain `gh pr merge` until the library task's CI lands, public on github.com/standards-lab, Apache-2.0; the library task scaffolds the base, `postgres`, and `nats` modules.
- plan: go-core's reactor and event packages are two tasks, core-reactor and core-event, each with its own go-core release; event is new design, the reactor a port of tested code.
- plan: service-reactors runs right after core-reactor, so go-core's reactor is proven on its one real consumer and the service's copies are deleted before events build on it.
- core-reactor: `reactor` ports go-web-service's `sdk.Reactor`, `Every`, `Wake`/`Waker`, `Draining`, and `Gate` with behavior unchanged, plus spike-messaging's `GraceWithin` (renamed `CancelWithin`); the gate is `reactor.Gate`. Rejected: `sync.RWMutex` (can't honor a context) and `x/sync/semaphore` (breaks go-core's standard-library-only line).
- core-reactor: the lifecycle coordination test sits outside the package, so `reactor` imports neither `lifecycle` nor `graph`.
- core-reactor: whether go-web-service uses `CancelWithin` in place of its hand-computed half of the shutdown timeout is decided in service-reactors.
- core-reactor: releases go-core v0.9.0, a minor: the task only adds API.
- core-reactor: currency re-run at start: go-core current; go-messaging has no mise tasks until the library task scaffolds them, so its currency command fails with nothing pinned.
- core-reactor: `Every` and `Wake` share one unexported tick loop (standards review); `Every`'s behavior is unchanged.
- core-reactor: `Gate` stays in `reactor`; the standards review raised a separate home, and the plan had already settled `reactor.Gate`.
- core-reactor: `Waker.Nudge`'s doc says a nudge after the source stops delivers nothing, though the nudge stays pending; left as worded, since it is harmless while a reactor is single use.
- core-reactor: go-core's capability map gains `graph`, which it had been missing; its seven packages count `process/processtest`.
- core-reactor: `Grace(d)` renamed `CancelAfter(d)` before release (BRIEF redirect): it names what happens when d runs out; `DrainTimeout` rejected, it collides with the coordinator's drain timeout.
- core-reactor: `GraceWithin(drain)` renamed `CancelWithin(drain)`; dropping the helper rejected, so the half-the-drain rule stays in one place.
- core-reactor: tests beyond the port cover `Ready` false while `Shutdown` drains, `CancelWithin`, and the start context's and source's values, and the unread-`Err` test was made able to fail.
- service-reactors: the sweeper sets its cancel-after period with `reactor.CancelWithin(shutdown timeout)` in place of computing half the shutdown timeout by hand, so the half-the-drain rule lives only in go-core; value unchanged (5s under the 10s default).
- service-reactors: fixes the three other statements go-core v0.8.0 made untrue ("any Ready joins readiness": composition root's package doc, README's guide to adding a service, readiness test's comment) beside the app.Wake comment.
- service-reactors: currency at plan: Grafana 13.2.3 -> 13.2.4 (patch) and go-core v0.8.0 -> v0.9.0 (adds only `reactor`) go in the upgrade slice; currency missed go-core because the proxy's version list lags the tag, so the slice checks the pin directly.
- service-reactors: the staged reactor and gate tests are deleted without porting, since go-core's reactor tests cover all of them.
- service-reactors: the cancel-after test runs under a 200ms shutdown timeout and pauses briefly after the sweeper reports Ready, so the pass reaches its wait on the gate; a short pause leaves no pass in flight and fails the test, so it can fail spuriously but never pass falsely. Rejected: a deterministic test, which needs a hook on go-core's `Gate` to observe the wait, a go-core change out of scope here.
- service-reactors: the CHANGELOG's [Unreleased] pins line now reads go-core v0.9.0 rather than listing both pins; older pins elsewhere in [Unreleased] (go-core v0.6.0 in the multi-library line, v0.7.0 in the UTC entry) stay, for a CHANGELOG-wide pin cleanup before the first cut.
- service-reactors: `sdk`'s package doc says the package stages request conventions only, dropping "lifecycle conventions" with the reactor and gate.
- core-event: ports spike-messaging's core/event with behavior and exported API unchanged, adding go-core's doc.go inventory, README, and capability-map entries. Rejected: cloudevents sdk-go v2.16.2 (json-iterator, google/uuid, zap, testify break go-core's standard-library-only line).
- core-event: typed data decoding stays in go-messaging's `Runtime.Consume[T]`; no `event.Decode[T]`: a consumer decodes into its own type, and Consume is the one caller.
- core-event: releases go-core v0.10.0, a minor: the task only adds a package.
- core-event: currency at plan: go-core current.
- core-event: Decode converts a parsed `ce-time` to UTC (escalation, utc-times standard), the one departure from the port's behavior-unchanged ruling; the spike returned the parsed zone.
- core-event: Encode writes `ce-time` in UTC as RFC 3339 with nanoseconds (`time.RFC3339Nano`), kept from the spike, so fractional seconds survive a round trip.
- core-event: `event` has no package README, since no go-core package has one; the brief's "package's README" is go-core's README entry and the doc.go inventory.
- core-event: `event`'s doc.go states each contract once and points to `Recorder.Emit`, `Encode`/`Decode`, and `Permanent` for the details (standards review).

- library: ports spike-messaging's messaging, outbox, inbox, memory, messagingtest, and postgres engine with behavior and exported API unchanged, adding only the error hook, the delivery attempt, poison-row quarantine, and the relay Timeout in Config, with the go-core v0.10.0 adaptations (GraceWithin becomes CancelWithin, no lifecycle.Register, logging.Throttle replaced by the hook).
- library: the base module admits sqlate and sqlate/query beside the standard library and go-core; README and STANDARDS.md dependency lines rewritten.
- library: a depguard rule holds the base module's production files to the standard library, go-core, sqlate, and sqlate/query, and admits sqlate/sqltest in test files only; the spike's split-check is not ported.
- library: only a corrupt row or a publish failure marked event.Permanent quarantines an outbox row, at once; transient failures count toward nothing but reach the error hook.
- library: quarantine is quarantined_at and reason columns on messaging_outbox, which the relay's claim skips; the unpublished partial index gains the condition.
- library: postgres Pending leaves quarantined rows out of its count.
- library: MaxDeliver exhaustion is detected by the Runtime's consuming reactor (handler fails on attempt == MaxDeliver); each provider puts the attempt in the handler's context; the Broker contract gains no exhaustion signal; messagingtest gains attempt cases.
- library: a source reports the errors it survives through a report function passed explicitly to Broker.Subscribe.
- library: the error hook is an Option on messaging.New, defaulting to logging each Failure at warn on the Runtime's logger.
- library: the postgres integration suite runs in a CI job on push to main and manual dispatch, against one compose Postgres; the release waits on it.
- library: this task enables go-messaging's "main" ruleset and Dependabot security updates before the first tag, in the CI slice.
- library: releases go-messaging v0.1.0 and postgres/v0.1.0; the nats module is scaffolded and untagged.
- library: currency at plan: go-messaging has no go.mod; the scaffold pins at latest (go 1.27.2, golangci-lint 2.14.0, go-core v0.10.0, sqlate v0.5.0, sqlate/postgres v0.5.0, sqlint v0.3.0, pgx v5.11.0).
