## Task brief · nats

```
Problem       go-messaging's nats module is an empty scaffold, so no service
              can run messaging on a real broker, and service-events has no
              provider to pin. spike-messaging's JetStream provider proved
              the design, but it predates the library's contract: it puts no
              attempt on a delivery, drops every error it survives, and
              provisions its stream from every broker, last writer wins.
              This task ports that provider onto go-messaging v0.1.0 and adds
              three things: the delivery attempt, error reporting through
              the source's report function, and stream ownership, so one
              broker owns the stream and every other binds it without
              provisioning it. It adds the NATS integration harness and
              releases the module.
Behaviors     1. The nats config block holds URL, Name, Stream, Prefix,
                 Owner, Duplicates, and MaxAge.
                 - Owner is a tri-state pointer to a bool; absent means not
                   the owner.
                 - Merge overlays each set field, including an Owner set to
                   false.
                 - Finalize defaults URL to nats://127.0.0.1:4222, reads
                   <PREFIX>_NATS_URL, _NAME, _STREAM, _PREFIX, _OWNER (parsed
                   as a bool), _DUPLICATES, and _MAX_AGE, and validates.
                 - Validate requires a URL. Stream must pass CheckName,
                   Prefix must pass CheckType, and Duplicates and MaxAge must
                   not be negative.
                 - On the owner, a positive MaxAge must be at least the
                   dedup window (Duplicates, or DefaultDuplicates when 0).
                 - On a non-owner, a set Duplicates or MaxAge fails
                   validation, and the error names the field.
              2. New validates its config and does no I/O. Before Start:
                 - the broker is not ready and Conn is nil;
                 - Publish and a source's Receive fail with ErrNotStarted;
                 - Shutdown returns nil.
                 Subscribe validates the subscription, as the conformance
                 suite requires.
              3. Start connects, bounded by ctx's deadline or 10s, and once
                 up reconnects without limit.
                 - The owner creates the stream, or updates it to its
                   config: file storage, limits retention, subjects
                   Prefix.>, the dedup window, and MaxAge.
                 - A non-owner writes nothing. It binds the existing stream,
                   and Start fails when the stream is missing or when none of
                   its subjects captures every subject under Prefix.
                 - A server that can't be reached fails Start. A failed Start
                   closes what it opened, and the broker can start again.
                 - A second Start fails with ErrStarted and opens nothing.
              4. Publish sends the event in binary content mode to
                 Prefix.<type>. Its Nats-Msg-Id is the event's
                 length-prefixed source followed by its id, so the stream's
                 dedup window drops a repeat. Publish returns once the stream
                 holds the event. It rejects what messaging.Encode rejects,
                 and a header value holding CR or LF.
              5. A source binds its durable consumer at its first Receive,
                 with a config derived from the normalized subscription:
                 - Name as the durable;
                 - StartAll as deliver-all and StartNew as deliver-new;
                 - explicit acknowledgement;
                 - the consumer's AckWait is the subscription's AckWait plus
                   AckMargin (250ms);
                 - MaxDeliver, with 0 meaning unlimited;
                 - one filter subject Prefix.<type> per type.
                 The same config binds the existing consumer, and a different
                 one fails Receive.
              6. A member pulls one message at a time, and pulls the next
                 only once the handler's outcome is settled.
                 - The handler's context carries the delivery's attempt (via
                   messaging.WithAttempt), taken from JetStream's delivered
                   count, and a deadline of receipt plus the subscription's
                   AckWait.
                 - nil acknowledges and waits for the server to confirm.
                 - An error marked event.Permanent terminates.
                 - Any other error naks with the subscription's RetryDelay,
                   or naks at once when RetryDelay is 0.
                 - An outcome settled after the deadline is dropped unsent.
              7. A source reports each error it survives to its report
                 function and keeps receiving:
                 - a message that doesn't decode, which it also terminates;
                 - a message whose JetStream metadata doesn't parse, which it
                   also terminates;
                 - an acknowledgement, nak, or termination that fails to
                   send;
                 - every failed pull other than an empty one. The source
                   reports not ready until a pull succeeds again.
                 A nil report discards them. A closed connection, or a
                 deleted consumer or stream, ends Receive with its error.
              8. Ready reports a started broker whose connection is up.
                 Shutdown drains the connection and returns once it closes;
                 when ctx ends first, it closes the connection and returns
                 ctx's error. Conn is the native handle, for request and
                 reply in a composition root.
              9. natstest gives each test its own stream.
                 - Open reads MESSAGING_NATS_URL and fails the test when it
                   is unset.
                 - Scratch takes a server URL and returns a stream name and
                   subject prefix unique to the test. When the test ends it
                   deletes the stream, tolerating one that nothing created.
              10. The provider passes messagingtest.Run with an owner broker
                 on a scratch stream per case. The integration suite adds
                 cases for:
                 - the owner's retention;
                 - a second owner converging on the stream;
                 - a non-owner binding, sharing events, and leaving the
                   stream's config unchanged;
                 - a non-owner's Start failing on a missing stream and on a
                   stream that doesn't capture its prefix;
                 - a late outcome being dropped;
                 - a deleted consumer ending Receive;
                 - an undecodable message being reported and terminated.
              11. The test-only NATS harness:
                 - Compose runs JetStream from a pinned nats:2.15.1-alpine
                   image, with its store on tmpfs and its health from
                   /healthz?js-enabled-only=true.
                 - Its port binds 127.0.0.1 at NATS_PORT (4225 by default),
                   and MESSAGING_NATS_URL follows it.
                 - integration:postgres and integration:nats each start only
                   their own service, run their module's suite, and stop it
                   whatever the result. integration runs both, and up and
                   down cover the whole stack.
                 - CI's integration job runs integration on push to main and
                   on manual dispatch, so a release waits on both suites.
              12. These describe the shipped provider:
                 - the README: the modules table, the usage section wiring
                   the nats broker and its owner switch, the development
                   tasks, and no scaffold lines;
                 - the nats and natstest doc.go export inventories;
                 - OnFailure's doc naming the nats source's failure volume
                   during an outage;
                 - the context capability map;
                 - the nats changelog at v0.1.0.
Test seams    the nats package's exported API, black-box. Config,
              before-Start behavior, and Start against a closed port run on
              the unit tier with no server. The provider runs through
              messagingtest.Run and its own integration cases under the
              integration tag, against the compose NATS through natstest.
Slices        1. Config and broker without a server: the config block with
                 Owner and the non-owner rejections, New, ErrNotStarted,
                 ErrStarted, and Start failing against a closed port (1, 2,
                 the unreachable case of 3). Pins at latest as code lands:
                 nats.go v1.54.0, go-messaging v0.1.0, and go-core v0.10.0.
                 Demo: `mise run check`; a non-owner config with max_age
                 rejected, naming the field.
              2. Harness: the compose NATS, natstest, and the
                 integration:postgres, integration:nats, and integration
                 tasks (9, 11 without CI). Demo: `mise run integration`,
                 with the postgres suite still green and a scratch stream
                 made and deleted on the compose NATS.
              3. Ownership, binding, and Publish: the owner's create or
                 update, the non-owner's checks, and the dedup id (3, 4).
                 Demo: the owner and non-owner integration cases, including
                 a non-owner's Start failing on a missing stream.
              4. The source: binding, one-at-a-time pulls, the attempt,
                 outcomes, and reporting (5–8, 10). Demo: the conformance
                 run green on NATS, including the attempt reaching
                 MaxDeliver, and an undecodable message reported and
                 terminated.
              5. CI: the integration job runs both suites (11). Demo: a
                 manual dispatch of CI on the branch, with the integration
                 job green on both suites.
              6. Docs and release prep (12). Demo: `go doc` of the nats
                 package, the README's usage with an owner, and the nats
                 changelog.
Out of scope  a dead-letter stream; InactiveThreshold and reaping abandoned
              durables; migrating a durable's binding config; reporting an
              exhaustion that ends in an AckWait overrun (JetStream's
              max-deliveries advisory); traceparent (v1.observability);
              request and reply beyond Conn; checking a non-owner's view of
              the dedup window or retention; any change to the base
              module's API, or a base release; a depguard rule on the nats
              module; wiring the provider into a service (service-events)
Door          two-way before the tag: code, the harness, CI, and docs are
              reversible. One-way at nats/v0.1.0: a published module version
              can't be unpublished. Its config keys (owner included) and the
              consumer config it derives (AckMargin included) bind the
              durables services create from it, though pre-1.0 a later
              minor may still change the API.
Release       nats/v0.1.0
```
