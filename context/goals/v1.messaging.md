## Task brief · core-reactor

```
Problem       Every program's process-lifetime entry points (a schedule, a
              demand wake, later a subscription) and its quiesce gate live
              only in go-web-service's sdk, so the template, go-messaging,
              and other services can't use them without copying. go-core
              gains a standard-library-only `reactor` package holding the
              source-agnostic reactor contract and the gate, as
              messaging.md places them, and releases it, so service-reactors
              can delete the service's copies next.
Behaviors     1. reactor.New(src, fn, opts...) returns a single-use Reactor.
                 Start launches the source and returns at once; the
                 reactor keeps the start context's values but not its
                 cancellation; a second Start errors.
              2. Shutdown drains in two phases: it closes the drain signal,
                 stops the source taking new occurrences, and waits for the
                 handling in flight; once the CancelAfter period passes it
                 cancels the handlers' contexts and reports that it did.
                 It returns ctx's error if its own context ends first.
                 Shutdown before Start retires the reactor so it never
                 starts; a later Shutdown returns nil.
              3. A handler's context carries the source's values and any
                 per-occurrence deadline the source set, but not the
                 source's cancellation. reactor.Draining(ctx) returns a
                 channel closed once Shutdown begins, and nil for a context
                 no reactor gave.
              4. Err yields the error that ends the source while running,
                 then closes when the source returns; a failure nothing
                 read is returned by Shutdown instead of lost.
              5. Ready is true only while the reactor runs and its source
                 is ready, and false once Shutdown begins.
              6. reactor.CancelWithin(drain) sets the CancelAfter period to
                 half of drain.
              7. reactor.Every(d) delivers the time on each tick, drops a
                 tick that comes due while the handler runs, ends on a
                 handler error, and panics if d is not positive.
              8. reactor.Wake(d) returns a *Waker that delivers on each tick
                 and on Nudge; any number of nudges before a delivery
                 coalesce into one, a nudge while the handler runs yields
                 exactly one delivery after it, a nudge before start is
                 delivered when it starts, and Nudge never blocks. It ends
                 on a handler error and panics if d is not positive.
              9. reactor.Gate's zero value is an open gate. Shared admits
                 any number of holders; Exclusive holds it alone; once an
                 Exclusive waits, no new Shared is admitted. An
                 acquisition whose context ends holds nothing, and an
                 abandoned Exclusive readmits the Shared holders it
                 barred. Each release is safe to call more than once.
              10. Under lifecycle.Coordinator, a Reactor as a graph node's
                  value is started with its layer, drained before the
                  nodes it uses, contributes a readiness check named by its
                  node (it is a ReadyStarter), and a source failure ends
                  the run as `run:`, with no registration code.
              11. reactor imports the standard library only, neither
                  lifecycle nor graph; go-core's go.mod gains no
                  requirement.
              12. The package's doc.go lists its inventory. The README
                  lists the reactor beside the other six packages.
                  go-core's working context names all seven packages in its
                  capability map and drops "staged" from the lifecycle's
                  description. CHANGELOG records v0.9.0 under Added.
Test seams    the reactor package's exported API (New, Start, Shutdown,
              Ready, Err, Draining, CancelAfter, CancelWithin, Every,
              Wake/Nudge, Gate.Shared/Exclusive); behavior 10 through lifecycle.New over a built
              graph.System, from a test outside the package
Slices        1. Reactor contract: Func, Source, Reactor, Option, Grace,
                 GraceWithin (renamed in slice 5), Draining, and Every, with the lifecycle
                 coordination test (behaviors 1–7, 10, 11). Demo: an Every
                 reactor in a graph System starts, reports ready, drains.
              2. Demand wake: Wake and Waker (behavior 8). Demo: nudges
                 coalesce into one prompt delivery.
              3. Quiesce gate: Gate (behavior 9). Demo: a waiting
                 Exclusive bars new Shared holders and a cancelled one
                 readmits them.
              4. Documentation and release notes: package doc, README,
                 capability map, CHANGELOG v0.9.0 (behavior 12).
              5. Rename: Grace → CancelAfter and GraceWithin → CancelWithin
                 across the reactor package's code, doc comments, doc.go,
                 tests (test names included), README, and CHANGELOG; the
                 unexported option field follows. No "grace" remains in
                 reactor's API or docs, except where it means graceful
                 shutdown in prose. Demo: CancelWithin(40ms) reports
                 "handlers cancelled after 20ms".
Out of scope  go-web-service's move onto go-core's reactor (service-
              reactors); the subscription source and anything broker-
              shaped (library, nats); the event package (core-event);
              any change to lifecycle or graph; go-web-service's
              sdk.Grace keeps its name until service-reactors deletes it
Door          two-way for the code and docs; one-way for the v0.9.0 tag,
              since a pushed module version is fetched by the proxy and
              pinned by the checksum database permanently
Release       v0.9.0
```

## Decisions

- plan: root is go-messaging, created by this plan; core-reactor names it in `repos` only for the record (the cli precedent, rooted in its new go-cli-sdk while its first task ran in go-core).
- plan: go-messaging takes go-cli-sdk's init set unchanged: kind code, `mise run check`, `mise run currency`, no release gate, plain `gh pr merge` until the library task's CI lands, public on github.com/standards-lab, Apache-2.0; the library task scaffolds the base, `postgres`, and `nats` modules.
- plan: go-core's reactor and event packages are two tasks, core-reactor and core-event, each with its own go-core release; event is new design, the reactor a port of tested code.
- plan: service-reactors runs right after core-reactor, so go-core's reactor is proven on its one real consumer and the service's copies are deleted before events build on it.
- core-reactor: `reactor` ports go-web-service's `sdk.Reactor`, `Every`, `Wake`/`Waker`, `Draining`, and `Gate` with behavior unchanged, plus spike-messaging's `GraceWithin` (renamed `CancelWithin`); the gate is `reactor.Gate`. Rejected: `sync.RWMutex` (can't honor a context) and `x/sync/semaphore` (breaks go-core's standard-library-only line).
- core-reactor: the lifecycle coordination test sits outside the package, so `reactor` imports neither `lifecycle` nor `graph`.
- core-reactor: whether go-web-service uses `CancelWithin` in place of its hand-computed half of the shutdown timeout is decided in service-reactors.
- core-reactor: releases go-core v0.9.0, a minor: the task only adds API.
- core-reactor: currency re-run at start: go-core current; go-messaging has no mise tasks until the library task scaffolds them, so its currency command fails with nothing pinned.
- core-reactor: `Every` and `Wake` share one unexported tick loop (standards review); `Every`'s behavior is unchanged.
- core-reactor: `Gate` stays in `reactor`; the standards review raised a separate home, and the plan had already settled `reactor.Gate`.
- core-reactor: `Waker.Nudge`'s doc says a nudge after the source stops delivers nothing, though the nudge stays pending; left as worded, since it is harmless while a reactor is single use.
- core-reactor: go-core's capability map gains `graph`, which it had been missing; its seven packages count `process/processtest`.
- core-reactor: `Grace(d)` renamed `CancelAfter(d)` before release (BRIEF redirect): it names what happens when d runs out; `DrainTimeout` rejected, it collides with the coordinator's drain timeout.
- core-reactor: `GraceWithin(drain)` renamed `CancelWithin(drain)`; dropping the helper rejected, so the half-the-drain rule stays in one place.
- core-reactor: tests beyond the port cover `Ready` false while `Shutdown` drains, `CancelWithin`, and the start context's and source's values, and the unread-`Err` test was made able to fail.
