## Task brief · blobfs-write-protocol

Problem
  go-web-service stages blobfs's write, ensure, and delete protocols in its `sdk` package so
  it can run a hook (its event emission) in the transaction that makes a file complete or
  deleting. The staging duplicates blobfs, can't reproduce blobfs's unexported deleting-file
  read, and pays an extra Hold statement to tell a retried delete. blobfs owns these
  protocols; it should offer the hooks itself, with no messaging dependency, before the
  sweeper task builds on blobfs.

Behaviors
  1. blobfs's WriteFile always completes the file in a transaction. Given `OnComplete(fn)`,
     fn runs in that transaction after the completion, with the call's context and the
     completed File; fn's error rolls the completion back and the write is abandoned as a
     failed write is today.
  2. WriteFile still refuses with the deleting refusal it names today when the file's
     delete refuses a deleting row (the branch the staging could not reproduce).
  3. EnsureFile takes `OnComplete` too; fn runs only when this call completes the file. A file
     found already complete, or completed by another writer, runs no hook.
  4. RemoveFile takes `OnDelete(fn)` as a RemoveOption (AtVersion also satisfies it); fn runs
     in RemoveFile's first transaction after the file is marked deleting. A retry, a delete
     that changes no row, runs no hook. fn's error rolls the transaction back and nothing is
     purged.
  5. Callers without hooks (the organization logo, blobfs's example) compile and behave as in
     v0.6.0; only a caller spreading a []VersionOption into RemoveFile must change.
  6. blobfs's guide documents both options and their signatures, and states that a hook on a
     branch mark must read the anchor's status under Directories.LockTree, since MarkDeleting
     accepts an anchor already deleting. deferred.md no longer lists the protocols as
     promotion candidates.
  7. blobfs's conformance suite's Protocols group covers the hooks (run, skipped, rollback),
     and the postgres module's integration tier runs it against PostgreSQL with GOWORK=off,
     requiring blobfs v0.7.0.
  8. go-web-service's upload, file delete, and seeded files run on blobfs's protocols with
     their hooks; every event they emit is unchanged in type, subject, data, and transaction.
  9. go-web-service's staged sdk.WriteFile, sdk.EnsureFile, and sdk.RemoveFile and their tests
     are gone; the docs that named the staging describe blobfs's protocols; the `sdk` package
     remains for Command.

Test seams
  blobfs: the scripted protocol unit tests and the conformance suite (Protocols group).
  go-web-service: the document domain's unit tier and the integration tier's event cases.

Slices
  Phase A — blobfs, its own pull request, released before Phase B:
  1. Upgrade: jdx/mise-action v5.1.1 -> v5.1.2; currency exits 0, check passes.
  2. Write hook: completion in a transaction, OnComplete, rollback, deleting refusal restored.
  3. Ensure hook: OnComplete only when this call completes.
  4. Delete hook: OnDelete in the first transaction, retry skips by the delete's changed-row
     flag, rollback purges nothing.
  5. postgres module requires blobfs v0.7.0 and runs the hook cases (GOWORK=off integration);
     guide, branch-mark rule, deferred.md rewrite; CHANGELOGs v0.7.0 and postgres/v0.5.0 cut;
     release brief; tag.
  Phase B — go-web-service:
  6. Pin blobfs v0.7.0 (root and tools/slab) and blobfs/postgres v0.5.0; upload and file delete
     move onto OnComplete and OnDelete, events unchanged.
  7. Seeds move onto EnsureFile's OnComplete; staging and its tests deleted; README,
     domain-architecture.md, sdk/doc.go and data comments rewritten; [Unreleased] entry.

Out of scope
  Promoting the branch mark (MarkDeleting reporting the anchor); the general sweeper and moving
  Sweep; go-messaging changes; any go-web-service release; blobfs CI running the integration
  tier.

Door
  one-way: the blobfs v0.7.0 and postgres/v0.5.0 tags. The go-web-service change is two-way.

Release
  blobfs: v0.7.0, postgres/v0.5.0
